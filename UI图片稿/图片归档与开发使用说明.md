# 时光书 H5 Demo UI 图片归档与开发使用说明

## 1. 归档目标

本目录用于保存时光书 H5 Demo 的页面视觉基准和后续开发需要的运行时图片资产。

12 张整页 UI 图片是第一版 H5 的 1:1 复刻基准，不是仅供参考的方向稿。React 页面必须真实还原图片中的页面结构、布局层级、尺寸比例、间距、字体层级、颜色、圆角、阴影、装饰、图片位置、按钮形态、聊天内容排布和页面状态。整页截图不能直接铺成背景，必须拆成真实可交互组件；但拆分组件不意味着允许自由改稿，最终渲染结果应与对应图片逐项对齐。图片中的测试数据也应先按原稿复刻，之后再通过数据层替换。

## 2. 目录结构

```text
UI图片稿/
├─ design-reference/             # 12 张整页设计稿，只用于视觉对照
├─ runtime-assets/
│  ├─ illustrations/             # 小精灵、亲子、入口横幅等可复用插画
│  ├─ decorations/               # 花朵、星星、相纸、胶带、书页等装饰
│  └─ demo-results/              # 文章、漫画、日记卡 Mock 成品
├─ asset-manifest.json           # 页面、路由、状态、占位和冲突的机器可读索引
└─ 图片归档与开发使用说明.md
```

## 4. 开发引用原则

### 4.1 整页稿

`design-reference/` 中的 12 张图片是对应页面和状态的 1:1 复刻验收基准。实现不是“做出类似风格”，而是逐项对齐：

1. 页面宽高比例、内容边界和滚动区域。
2. 顶部栏、卡片、聊天区、预览区、底部操作区和底部导航的位置。
3. 元素尺寸、间距、内边距、圆角、边框和阴影。
4. 字体层级、字重、行高、颜色和对齐方式。
5. 插画、照片、装饰、按钮、输入框、标签和状态徽标的视觉位置。
6. 对应页面状态下的可见文案、测试数据和交互结果。

“1:1 复刻”不等于把整张截图当作背景图。必须拆成真实 DOM、CSS 和可交互组件，因为按钮、输入框、聊天消息、图片上传、底部导航、弹层和预览操作都要能实际工作；但是拆分实现后，截图结果必须与基准图逐项对齐。

以下内容按设计稿中的原样实现，但数据层必须可替换：

1. 测试人物名、头像、日期、数量、标题、正文和聊天文案。
2. 文章、漫画、日记卡的测试成品。
3. “创作中”、已读时间、轮次等测试状态。

图片中的系统状态栏（`9:41`、信号、电池）属于设计稿画布占位，不作为 H5 页面业务 DOM；页面主体从设计稿状态栏下方开始，并保持与图片主体一致的空间关系。

### 4.2 运行时插画和装饰

真正由 H5 引用的插画应单独导出到 `runtime-assets/illustrations/`。装饰元素放入 `runtime-assets/decorations/`。

建议优先准备：

- `timebook-spirit.png`
- `parent-child-reading.png`
- `generation-banner.png`
- `article-entry.png`
- `comic-entry.png`
- `diary-card-entry.png`
- `paper-background.png`
- `flower-divider.png`
- `photo-corner-tape.png`
- `book-page-frame.png`

能用 CSS Token、边框、渐变和伪元素实现的简单装饰不要额外切图，以减小包体并提高响应式稳定性。

### 4.3 Mock 成品

文章、漫画和日记卡预览中的测试结果放入 `runtime-assets/demo-results/`，由 `MockWorkflowAdapter` 返回，不要从整页截图里截取包含按钮和导航的区域。

建议文件：

- `article-graduation-preview.png`
- `comic-graduation-6-panels.png`
- `diary-card-first-bike.png`

如果文章预览最终由 HTML 书页组件渲染，则文章正文不需要整图，只保留书页装饰框和示例正文数据。

## 5. 与技术实现的对应关系

| 图片资产 | 开发模块 | 使用方式 |
| --- | --- | --- |
| 12 张整页稿 | 每个页面和状态的 1:1 视觉验收 | 不作为背景图；开发时逐页对照并做截图比对 |
| 小精灵和亲子插画 | `src/assets/illustrations` | 按设计稿中的位置、尺寸和裁切方式真实渲染 |
| 花朵、相纸、书页 | `src/assets/decorations` | 按设计稿中的位置、尺寸、透明度和层级使用 |
| 漫画/日记卡 Mock 图 | `src/assets/demo-results` | `MockWorkflowAdapter` 的 `GenerationResult.imageUrls`，还原设计稿成品区域 |
| 文章示例正文 | `src/data/mockResponses.ts` | `GenerationResult.title/text`，按文章预览稿的书页排版渲染 |
| 页面图片映射 | `asset-manifest.json` | 追踪每张 1:1 复刻稿的路由、状态和测试数据 |

建议前端工程建立以下结构：

```text
src/assets/
├─ illustrations/
├─ decorations/
└─ demo-results/
```

如果前端工程与文档目录分开，不要让运行时代码直接依赖 `UI图片稿` 的相对路径。开发时将已确认的运行时资产复制到 `src/assets`，整页参考图仍留在当前目录。

## 6. 权威业务边界

出现设计稿与文档不一致时，业务行为按产品文档判定，视觉表现按对应图片稿 1:1 复刻。也就是说，不能因为业务层使用了动态数据，就随意改变图片稿的页面排布；只能替换数据，不得改动视觉结构。

业务规则优先参考：

1. `时光书H5 Demo用户路径与交互逻辑文档.md`
2. `时光书H5 Demo前端设计文档.md`
3. `时光书H5 Demo对抗性审查与修正建议.md`
4. `时光书H5 Demo技术实现文档.md`

视觉规则优先参考：

5. 对应编号的整页 UI 图片稿

必须遵守：

1. 底部主导航固定为 `时间轴 / 生成 / 我的`。
2. 生成首页固定有 AI整理回忆、文章、漫画、日记卡四个入口。
3. 三个生成页以多轮聊天为主体。
4. 来源回忆可选，允许从生成首页直接聊天补充素材。
5. 生成完成后在当前生成页进入 `preview`，不跳独立结果页。
6. 我的页面只查看已保存作品，不设置新的创作 CTA。
7. 漫画不承诺真人还原。

## 7. 已识别的设计稿冲突

1. `mine-works.png` 的底部导航保留了中心生成 Tab，这是全局导航本身，可以存在；但页面主体不能再增加“立即生成”按钮。
2. 部分预览稿右上角仍显示“创作中”。实现时应在工作流完成后显示“已生成”或预览状态，`创作中` 只对应 `chatting/generating`。
3. 图片中的 `9:41`、信号、电池为设计工具状态栏，不进入 H5。
4. 图片中的已读时间、测试人物、日期、数量、作品和结果均为种子/占位数据。
5. 漫画与日记卡聊天中的快捷选项只能帮助用户快速回答，不能把页面退化为选择题表单。

## 8. 图片质量要求

原图归档时应保持：

1. PNG 或无损 WebP，优先保留设计工具导出的 PNG。
2. 不重复压缩，不从聊天预览截屏。
3. 文件名使用小写英文和连字符，避免前端构建工具和部署环境的路径兼容问题。
4. 记录原始宽高；整页稿应至少保持当前手机设计稿清晰度。
5. 运行时大图按最长边和实际展示尺寸输出 1x/2x 版本，避免把超大整页图打进 H5。

## 9. 1:1 复刻验收要求

完整的逐页截图流程、量化误差门槛和最终交付定义见 `1比1复刻交付与截图验收标准.md`。每个页面开发结束后必须先截图检查，通过当前页面视觉闸门后才能继续下一页。

每个页面至少要完成以下检查：

- [ ] 12 张原图已导入 `design-reference/`，文件名与清单一致。
- [ ] 图片数量、原始宽高、文件格式已核对。
- [ ] 页面主体尺寸与设计稿比例一致，360px、390px、430px 宽度不发生横向溢出。
- [ ] 顶部栏、主体卡片、聊天列表、输入区、固定底部按钮、底部导航的位置与设计稿对齐。
- [ ] 颜色、字体层级、行高、圆角、边框、阴影和纸张背景已按设计稿复刻。
- [ ] 插画、照片、装饰和成品图的比例、裁切、层级和大致位置与设计稿一致。
- [ ] 设计稿中的每个按钮和输入区都是真实可交互元素，不是图片上的假控件。
- [ ] 聊天态、草稿弹层态、生成中态、预览态和已保存态能够通过真实状态切换。
- [ ] 视觉回归截图与对应设计稿逐页比对，不能只验证“功能能点通”。
- [ ] 可复用插画从源设计资产单独导出；如果暂时只有整页图，必须先明确标记为临时素材，不得默认为最终资产。
- [ ] 漫画和日记卡 Mock 成品不包含导航、按钮和聊天 UI。
- [ ] `asset-manifest.json` 中每张图都能对应到一个路由和状态。
- [ ] 图片稿的状态栏不进入真实页面，但状态栏下方的页面主体空间关系要保持一致。
- [ ] 测试人物、日期、数量和文案从种子数据驱动，未来替换数据时不改变页面结构。
